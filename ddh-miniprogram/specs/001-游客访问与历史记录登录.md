# Spec 001：游客访问与历史记录登录

## 状态

待确认

## 背景

微信小程序审核指出，当前小程序在用户一进入时就要求进行授权登录，不符合“先浏览体验功能服务，再自行选择登录”的要求。

当前代码表现为：

- 首页提供“新建筛查任务”和“查看历史记录”两个入口。
- 首页点击上述入口时都会先做登录校验。
- 历史记录页在未登录时会直接跳转登录页。
- 登录页目前承担了较强的前置入口角色。

## 问题定义

需要把“登录”从默认前置门槛调整为按需触发，仅在真正需要用户身份的场景提示登录。

## 本步骤目标

确认并冻结新的访问策略，作为后续代码改动依据。

## 目标策略

### 1. 游客可直接进入首页

小程序启动后默认进入首页，不自动跳转登录页，不因为未登录阻断浏览。

### 2. 主要功能允许未登录使用

用户在未登录状态下，可以直接进入并使用主要体验功能。

当前按项目现状，主要功能默认指：

- 新建筛查任务
- 进入病例填写/分析主流程
- 查看已生成的当前结果（若该流程本身不依赖账号）

### 3. 历史记录按需登录

用户点击“查看历史记录”时，如果尚未登录，再弹出或跳转登录提示。

登录完成后，应回到历史记录功能，而不是把用户丢回一个无关页面。

### 4. 登录页角色降级

登录页不再作为首次使用的强制入口，而是一个按需调用的辅助页面。

## 建议实施范围

后续代码实施预计涉及：

- `app.json`
- `pages/index/index.js`
- `pages/index/index.wxml`
- `pages/history/history.js`
- `pages/login/login.js`
- `pages/login/login.wxml`
- `utils/auth.js`

## 验收标准

确认后，后续实现必须满足：

1. 冷启动进入小程序时，不出现强制登录拦截。
2. 用户未登录时，可以从首页进入主要功能流程。
3. 用户未登录时，点击“查看历史记录”才触发登录提示。
4. 登录成功后，可继续进入历史记录页面。
5. 已登录用户的现有使用路径不被破坏。

## 非目标

本步骤先不处理以下内容：

- 用户体系重构
- 服务端鉴权改造
- 历史记录真实云端同步
- 手机号、头像、昵称的完整资料采集设计

## 风险与注意事项

- 当前本地“历史记录”看起来依赖本地缓存，不一定真的需要服务端账号；但基于你的需求，本次仍按“历史记录需要登录”执行。
- 如果病例分析主流程里还隐藏了其它登录拦截，需要在实施时补充排查。
- 当前目录不是 Git 仓库，最终提交前需要确定 Git 管理方式。

## 待你确认

请确认以下判断是否正确：

1. “新建筛查任务/主流程”未登录也要可用。
2. 只有“查看历史记录”需要登录。
3. 登录成功后默认进入历史记录页。
4. 本次先不删除登录页文件，只把它改成按需进入。
