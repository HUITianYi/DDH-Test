# AGENT.md

## 目标

本项目按照“先写 spec、确认后实施、实施后验证、最后提交”的流程推进，确保每一步范围清晰、可回溯、可验收。

## 协作流程

1. 我先分析当前代码与影响范围。
2. 我为当前步骤编写对应的 spec 文件，放在 `specs/` 目录。
3. 你确认该 spec 后，我再开始实施该步骤的代码修改。
4. 我完成该步骤后，补充验证结果与变更说明，再进入下一步 spec。
5. 全部步骤完成并得到你确认后，再整理 Git 提交。

## 本次整改的总目标

围绕微信小程序审核意见完成整改：

- 小程序首次打开时，不能在用户尚未浏览功能前强制要求手机号、头像、昵称或微信授权登录。
- 用户未登录时也可以使用主要功能。
- “查看历史记录”属于需要身份识别的能力，可在用户点击该功能时再提示登录。

## 分步原则

- 每一步只处理一个清晰目标，避免把流程调整、页面改造、文案修正、验证混在一起。
- 每一步必须有明确验收标准。
- 未经确认，不提前实施下一步。
- 若发现范围扩大或存在隐藏风险，先补充 spec 再继续。

## 建议步骤

### Step 1

定义游客访问与登录触发策略，明确哪些页面允许未登录访问，哪些功能在触发时要求登录。

### Step 2

根据已确认的策略修改首页、登录页、历史页及认证工具代码，移除首次进入时的强制登录链路。

### Step 3

修正文案与交互提示，让用户知道主要功能可直接体验，只有历史记录需要登录。

### Step 4

做回归验证，确认首页进入、主要功能使用、历史记录登录拦截都符合预期。

### Step 5

整理最终说明并提交 Git Commit。
